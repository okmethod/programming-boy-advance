## バージョニングの原則

素質は「**何が得意か（系統）**」×「**どこまで開花したか（バージョン）**」で表す。

- **系統（Family）**: 取れるコマンドの方向性＝**能力の性格**。攻撃が得意／移動が得意、など。B面＝どのライブラリ・命令セットを積んだベースイメージか（`FROM`）。
- **バージョン（Version）**: 同じ系統の中での**成熟度**。上げるほど、使える命令セット（プログラムブロック）が増え、コマンドの単価（上昇 BP・要求 CP）が下がる。B面＝ベースイメージのタグ（`イメージ:版`、例 `turtlogo:1.0 → 1.1 → 2.0`＝メジャー.マイナー）。

> **「版」の二重に注意**: 素質バージョンは**土台（ベースイメージ）の版**＝持って生まれた才能の世代／プログラムの版＝書き直した履歴。  
> [overview.md](./overview.md) のオートマトンレジストリが持つ版管理は**自分のプログラム改良の版**（オートマトンイメージのタグ）で、別物。

### マイナー / メジャー

| 種別     | EN    | 大まかな提供                                             | B面（イメージ版） |
| -------- | ----- | -------------------------------------------------------- | ----------------- |
| マイナー | minor | 既存系統の微拡張（命令の追加・単価の改善）＝**成長**     | `1.0 → 1.1`       |
| メジャー | major | 新しい命令ファミリー／パラダイムの獲得＝**開花（覚醒）** | `1.1 → 2.0`       |

このマイナー／メジャーが、命令セット解放の**粒度ダイヤル**になる。  
どのバージョンをいつ解放するかで、レベルデザインの刻みを素質の版という世界観で正当化できる。

### 後方互換の原則

同一系統では、**版を上げて付与される命令セットは単調増加**する（上位版の集合 ⊇ 下位版の集合）。

ただし、これは安全な版上げを保証する設計原則であって、切替可否の判定機構ではない。
編集時に実際にベースイメージを切り替えてよいかは、**版・系統に依らない独立した互換性ガード**で判定する。

## 系統一覧（WIP）

| JP 名（ファミリー名） | EN（ベースイメージ名） | 方向性（取れるコマンドの性格）           | 元ネタ                       |
| --------------------- | ---------------------- | ---------------------------------------- | ---------------------------- |
| カメの歩み            | `turtlogo`             | 素朴な移動。移動・向き変えなどの基本動作 | Logo（タートルグラフィクス） |

> 名付けは「**動物×プログラミング言語名のもじり**」を基本方針とする。  
> A面では単なる固有名詞（`turtlogo` 等）と `:1.0` のような版で呼び、B面で出自となった言語解説に繋げる。  
> 動物の採用基準は **UI でアイコン表現できること**（固有名詞では動物名が崩れることがあるため、アイコン＋ JP 名で「どの動物か」を担保する）＋**もじりが自然に成立すること**。  
> 採用候補の動物: ウサギ, ヘビ, フクロウ, ゾウ, ネコ, ブタ, サカナ, パンダ, コウモリ, アヒル, イルカ, ...

## 各系統のバージョンと提供内容（WIP）

各系統は、バージョンを重ねるごとに「できること」を広げる。  
以下は設計のたたき台で、**各バージョンが具体のどのブロックを提供するか／いつ解放するか**は [program-blocks.md](./program-blocks.md) と [design/ux-level-design.md](../design/ux-level-design.md) に対応づけて確定する。

> 系統の数・名称・EN、各バージョンの提供内容は暫定。  
> 系統間の兼ね合い（例: 条件分岐はクエリと組んで活きる）や解放順序は Tier／Chapter で調停する。

### カメの歩み（turtlogo）

| バージョン | 大まかな提供                       |
| ---------- | ---------------------------------- |
| v1         | 基本の行動（移動・向き変え・待機） |
| v2         | 制御の獲得（くりかえし・条件分岐） |
| v3         | 攻撃の獲得（戦える）               |

序盤を「攻撃なしで、移動と読解で勝つ」構成にするため、攻撃コマンドは最後（v3）に解放する。

# プログラム実行モデル

自キャラ/敵キャラのプログラムを、共通クロックに沿って実行するためのモデル。

---

## 方針

**プログラム＝命令木（AST）**とし、**ドメイン層の再開可能インタプリタ**が、**1コマンドずつ**解釈する。
バトルループは共通クロックの各ステップで、**行動順（priority）に従い1体ずつ逐次に**コマンドを適用し、決定的に勝敗へ進める。

## なぜ（判断の指針）

- **決定的・再現可能**: 「敵の動きを読んで対処する」という看板メカニクスは、敵が毎回同じ動きをする前提で初めて成立する
- **Worker 不要でテスト可能**: ドメイン層が純TSの決定的関数になり、ブラウザなしで Unit テストできる
- **観戦・デバッグが自然**: 1コマンド単位で止められるため、観戦・一時停止・「なぜ負けたか」の追跡ができる
- **共通クロック**: 対戦の公平性とタイミング勝負の前提

### 実行の粒度（tick モデル）

**逐次ステップ＋ターン順適用**とする。  
インタプリタが「1コマンド（move/turn/attack/wait）」ずつ `yield` し、バトルループは各クロックで**行動順に1体ずつ**コマンドを解決する。  
後手は先手の行動を反映した最新状態を見て判断・行動する。

なお、全オートマトンが同じ pre 状態を見て同時に動く「ロックステップ同時適用」も検討したが、不採用とした。  
判断理由は以下の通り。

- **2体が同じマスへ同時侵入しようとしたときに双方を不成立にする**特殊処理が要り、正面衝突が「1マス空けて膠着→引き分け」になる副作用があった（初期距離の偶奇で勝敗が変わる）。
- ターン順に1体ずつ解決すれば、後手は埋まったマスへ進めず**隣接が自然に成立して交戦に入る**。衝突回避のアドホックな特殊処理が不要になり、挙動も「1体ずつ順に動く」という単一のメンタルモデルで説明できる。

代償として**先手に有利（先制）**が生じるが、これは欠点ではなく設計レバーと捉える。  
行動順は各オートマトン（＝プロセスのメタファー）が持つ **`priority`（スケジューリング優先度）が高い順**で決める。  
`priority` は**固定値**で、現状はプレイヤー（ally）を高くして先手固定。同値は定義順（安定ソート）。

> 将来この値を設計・調整する余地を残すが、当面は固定・動的化しない（YAGNI）。

### 再開可能性の実装

- **JS ジェネレータ**（`function*` で action を yield）で「再開可能」を実現する。小さなツリーウォーク・インタプリタを generator 化すれば足りる
- 明示的バイトコード VM（PC＋スタックの明示シリアライズ）は**不要**。途中状態の保存は要らず、**リプレイは「同じシード＋同じプログラムを頭から再実行」で決定的に再現**できるため
- **決定性のルール**: ドメイン層で wall-clock / 無シードの乱数を使わない。ばらつきが要る場合は**シード付き PRNG を状態に持つ**

## 最小契約（型の骨子）

この4つを固めれば、ストア機構・コンテンツ方式・ブロックUI は後から噛ませられる。
**型の正本（SSoT）はコード**に置き、ここでは骨子だけを示す（シグネチャの転記はドリフト源になるため避ける）。

1. **プログラム＝命令木（`Program` / `Stmt`）**: ブロックUIが出力する AST。`call`（コマンド）/ `repeat` / `if` / `while` の4種で構成する。JS 文字列ではない
2. **世界の状態（`BattleState`）**: 不変・readonly。グリッド・オートマトン・クロック・乱数シード・ログ・勝者を持つ
3. **再開可能インタプリタ（`run`）**: プログラムを1コマンド（move / turn / attack / wait）ずつ yield するジェネレータ
4. **バトルループ（`applyAction` ＋ `runBattle`/`recordBattle`）**: `applyAction` が1体の1コマンドを状態に適用し、`runBattle` が各クロックで行動順に1体ずつ呼び出して決定的に勝敗へ進める

センサ（`壁がある?` `敵が近い?` 等）は `BattleState` を読む純粋関数＝決定的。敵プログラムも同じ命令木を流用する。

> 型の定義は [domain/models/types.ts](../../skeleton-app/src/lib/domain/models/types.ts)、公開 API は [domain/index.ts](../../skeleton-app/src/lib/domain/index.ts) が正。本節と食い違う場合はコードを優先する。

## 諦めるもの

- **eval-in-Worker の自由度 / 生 JS 入力**: 現状の `safeWorkerScript.js`（JS を eval して Worker 実行）が持つ「任意の JS が動く」自由度は手放す
- これは将来の「上級者向け生 JS モード」のオプションに格下げする（当面は作らない）。初学者はブロック＝命令木で十分カバーできる
